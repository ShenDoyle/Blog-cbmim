Agent 应该是今年最火热的工具了，但是实际使用的过程中，很多人的体验不佳，总是出现任务不达预期的情况。

<!--more-->

这是目前无法避开的问题，任务一旦跑偏，可能已经改了十几个文件，消耗了大量上下文和 token，最后还会一本正经地告诉你：「任务已完成。」

之前我尝试一个方案，用网页版的 DeepSeek 帮我规划和优化 prompt 提示词，效果确实比我自己的词好很多，而且大大减少了 AI 执行任务的时候出现的问题。

但网页版的 AI 这点好用，缺只能给方案，不能直接操作本地环境。于是我经常需要在两个 AI 之间复制指令、传递结果，自己成了搬运工。

**前两天我突然想到：能不能让网页版 AI 负责思考，本地 Agent 负责执行？**

所以 Starpilot（星舵）就在这个想法下诞生了。

GitHub：[https://github.com/ShenDoyle/Starpilot](https://github.com/ShenDoyle/Starpilot)

## 一、星舵的核心思路

星舵是一个面向本地 Agent 的 Skill，通过浏览器连接网页版 AI，让规划、执行和反馈形成一个闭环。

分工很简单：

- **网页版 AI**：负责方案、任务拆解和验收标准。
- **本地 Agent**：负责执行、采集证据和反馈结果。
- **用户**：负责需求确认、授权和最终验收。

整个流程：

```
需求确认 → 方案规划 → 步骤拆解
                       ↓
阶段验收 ← 结果反馈 ← 本地执行
   ↓
下一阶段规划
```

它不是简单地让两个 AI 互相聊天，而是通过需求卡片、`journal`、`handoff.md` 等机制保存项目状态，确保跨阶段、跨对话也能继续工作。

核心原则是：**允许 Agent 自主执行，但不允许它擅自改变目标；允许它处理问题，但必须留下决策记录。**

## 二、几个亮点

**1. 网页 AI 回复判定**

针对 WEBAI 的网页架构，做了一套专门的工作流，识别实际对话的情况，在会话结束的第一时间知道结果出来了，然后获取结果执行任务。不会盲目空等，也不会截取一半内容就执行任务。

已经跑过的如 DeepSeek、ChatGPT 等页面经过实际的项目测试，实际的工作流进行了固化，可以直接使用。对于页面改版和新的 WEBAI ，也有一套工作流可以自动摸清情况。

**2. 写操作四步闸门**

所有重要写操作采用：

```
演练 → 批准 → 正式执行 → 写后核验
```

默认先演练，批准需要限定范围和有效期。执行中断后先复核状态，绝不盲目重发，避免重复修改。

**3. 自主恢复**

遇到操作连续失败、对话被抢占、网页状态异常等情况，Agent 不会无限重试，而是收集现场信息，重新建立对话或交回网页版 AI 调整方案。

自主恢复不等于随意发挥。超出授权范围、需要人工登录验证或环境彻底不可用时，仍然需要用户介入。

所有自主决策都会在阶段收口时汇总。

## 三、为什么使用网页版 AI，而不是 API？

主要考虑三个方面：

- 直接使用已有订阅中的模型能力，不需要额外管理 API 和上下文费用。
- 可以直接把截图、报错、文档等真实材料交给 AI 分析。
- 复杂任务可以保留完整的方案和多轮讨论，不必反复压缩上下文。

代价也很明显：速度较慢、依赖网页 DOM、暂时不支持同一项目并行执行。

目前已实测的平台包括：

| 平台       | 状态  |
| -------- | --- |
| DeepSeek | 已实测 |
| ChatGPT  | 已实测 |
| Kimi     | 已实测 |
| Gemini   | 已实测 |
| 豆包       | 已实测 |
| Claude   | 待标定 |

新平台可以通过 `probe` 检测输入框、发送按钮、消息容器和完成信号，标定通过后即可接入。

## 四、安装和使用

项目使用 Python 标准库，不需要安装额外的 Python 第三方包。浏览器自动化由腾讯开源的 BrowserSkill（bsk）负责。

基本环境：

- Python 3.9+
- BrowserSkill（bsk）
- Chrome 或 Edge 及对应扩展
- 已登录的网页版 AI 账号

克隆项目：

```
git clone https://github.com/ShenDoyle/Starpilot.git
```

完成 bsk 和浏览器扩展配置后，运行环境检查：

```
python scripts/env.py
```

也可以直接让本地 Agent 安装：

```
安装并配置 Starpilot：
https://github.com/ShenDoyle/Starpilot

检查 Python、bsk 和浏览器扩展连接状态，
完成后报告环境检查结果及需要人工处理的事项。
```

安装后直接告诉 Agent：

> 用星舵做一下这个项目。

或者：

> 让网页版 AI 先规划，再由你执行。

## 五、适合什么任务？

星舵更适合步骤较多、需要持续执行和验收的工作：

- 大型项目开发、代码重构。
- 多份文档整理、知识库重构。
- Excel 数据清洗、跨表对账。
- 批量运营任务和自动化检查。
- 多方案调研、技术选型。

改个错别字、查个语法就没必要使用它了。建立项目状态和执行闭环本身也有成本。

## 六、目前还不够完善的地方

目前仍有几个明确的短板：

- 升级包尚未实现完整的签名和哈希校验。
- 提示词 A/B 测试样本不足。
- 跨天级别的无人值守运行尚未充分验证。
- Windows 下偶发浏览器连接中断，需要进一步完善 daemon 常驻机制。
- 多任务目前采用排队执行，不支持真正并行。

这些都是后续需要继续完善的方向，使用过程中遇到一些体验不符合我的描述，也可以通过 issues 告诉我。

## 七、意外收获

本意是想通过工具出更好的结果，但是测试的时候我发现，当前的工作流还可以大大减少 Token 的消耗。

网页 AI 直接用免费的账户即可，给出的 Prompt 通常很详细，约束也非常的充足，Agent 不需要非常强的模型就可以根据要求完成任务，即便出现问题，也会被 网页 AI 的后续 Prompt 纠正，无需人工的介入。

当然你想仔细检查每一步，也可以选择人工值守的方式执行任务，这样每一步执行指令出来了，Agent 都会问你这么做可不可以。

## 写在最后

我做了十来年运营，不是科班开发。

做星舵的过程中，我越来越觉得，AI Agent 真正需要解决的，不只是能力问题，还有执行纪律。

一个工具可以不够聪明，但必须知道自己做了什么、哪些事情没做到，以及为什么没做到。

**我想要的不是一个永远告诉我「任务已完成」的 AI，而是一个能够把事情做完、把过程留下来、出了问题也能说清楚的执行系统。**

这就是 Starpilot。
